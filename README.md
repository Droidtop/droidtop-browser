# droidtop Browser

droidtop's own browser: [Iceraven](https://github.com/fork-maintainers/iceraven-browser) (Firefox for Android,
GeckoView) under droidtop's package `dev.droidtop.browser`, signed with a key derived from the droidtop root.

Why it exists (owner, 2026-11-21): droidtop needs a browser it can extend, and the system WebView a device ships
cannot always be updated. The Retroid Pocket 5's ROM allows only its own `com.android.webview` 109, which
Cloudflare's browser check now refuses, so F95zone's sign-in and check pages loop forever. GeckoView brings its
own current engine. The browser will carry droidtop's web session (plugin API G3: sign-in, browser checks,
`open_in_session` downloads) as an application-interface plugin, so droidtop can show those pages in Gecko
instead of the system WebView. Everything goes through the plugin API, like any plugin.

## Branches

This repository is a fork, so it follows the upstream-app plugin model:

- **`plugin-core`** (the default branch) holds only droidtop's recipe: `droidtop/apply.sh` (package, name),
  the workflows, this README, and the line pin in `plugin-line/lines/stable/line.json`. Every change lands here.
- **`upstream-sync`** is Iceraven's `iceraven` branch, untouched. It only ever fast-forwards
  (`.github/workflows/sync-upstream.yml`); a new upstream commit comes back as a `ci/upstream-stable-<sha>`
  branch that moves the pin.
- **`plugin/stable`** is the pinned upstream commit with `plugin-core` written over it, generated by
  `tools/plugin_line.py compose stable --commit` from Droidtop/droidtop-platforms, never edited.

The other branches are Iceraven's, kept as the fork brought them; `old/upstream-sync-2022` is Iceraven's own
stale branch of that name, moved aside.

## Building

`.github/workflows/browser-build.yml` composes the line in the job (upstream at the pin, this branch over it),
runs `droidtop/apply.sh` and Iceraven's own build steps, and signs the arm64-v8a and x86_64 APKs with
`APK_KEYSTORE_BASE64` / `APK_KEYSTORE_PASSWORD` / `APK_KEY_ALIAS`. Those are derived from the droidtop root
(`plugin-key-provision apk`); the certificate is fixed for good, because Android installs an update only when
it is signed with the same one.
