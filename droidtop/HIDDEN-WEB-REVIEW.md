# Hidden Gecko document capability: source review and implementation boundary

2026-11-27. This is a bounded static review and internal provider implementation, with its public relay disabled pending joint source review and CI. No local Android build or live app/device tests were run. Visible pages use a separate runtime. Source references pin Mozilla's `FIREFOX-ANDROID_160_0_RELEASE`, matching Browser's 160.0.1 engine family.

## Host gap

Droidtop's `PluginBrokers` still routes `webFetch` to `WebFetch.fetch` and hidden opens to `HiddenWebSession.open`, both system WebView implementations. `HostNetApis.request` uses the hidden fetch for challenged GETs after `hopCheck` and `reach`, but its old callback drops the requesting record and redirect authorization callback. A null hidden result can fall through to HTTP. Reusing cookies and user agent across these engines does not establish equal browser/network fingerprints or solve challenge execution on an obsolete system WebView.

`WebFetch` currently returns a bounded document answer after allowing scripts to settle; `HiddenWebSession` has constrained PERSON/EXPIRED/HANDOFF/DOWNLOAD outcomes. These are separate requirements from the visible `web.view` surface. Store OAuth and key panes are also separate capabilities; they must not be represented as arbitrary script access through this GET boundary.

## Canonical contract and disabled consumer

The named relay is `web.hidden.v1`, negotiating both `web.document.get.v1` and `web.runtime.isolated.v1`, with API 30 minimum. The hidden session uses an owned drained render surface; visible interaction remains a real GeckoView. `IWebHiddenHost` is mixed Binder: connected(provider, capabilities), one-use takeRequest(token), authorize(token, url, kind), result(token, bounded metadata), unavailable(token, reason). Provider operations are start(token), one-use body(token) returning a reliable PFD pipe, and cancel(token).

The immutable GET request contains op, HTTPS URL, cookies for the initial host, maxBytes at most 128 KiB, deadline at most 30 seconds and a host-owned operation proxy descriptor. No caller scripts, selectors, request bodies or arbitrary header bridge. Unsupported custom credential headers fail explicitly. Authorize rechecks current plugin/provider grants for document, frame, resource and redirect hops. The CONNECT gateway checks and connects the same resolved address, retains actual addresses for later grant revalidation and prevents fresh DNS from concealing reused private connections. There are no Cloudflare/CDN exceptions. Missing dependency permissions are an explicit outcome.

After takeRequest, failures are terminal and cannot silently retry via HTTP/system WebView. A document result must be untruncated, with an independently authorized final URL, bounded metadata, exact body length and reliable-pipe EOF/error checks. Oversized HTML or JSON is failure, never success containing partial syntax. At most four operations globally. hiddenOpen needs a distinct capability and its existing user-driven browsing policy; blindly imposing net.http scope on visible file-host navigation would change that behavior.

The AIDL and machine contract are consumed from canonical mytop-plugins `07aa739fcefdab02f70e017811e0336cfffc65ab` (0.3.5 candidate). Consumer code does not duplicate those interfaces. The capability remains unadvertised until the host/provider joint review and exact-head CI gates pass.

## Supported pieces verified in pinned source

- `GeckoSession.NavigationDelegate.onLoadRequest` returns an asynchronous GeckoResult of AllowOrDeny. Its LoadRequest documentation explicitly describes a second callback for an HTTP redirect target. `onSubframeLoadRequest` handles subframes. These are navigation controls, not proof of all network traffic interception.
- A privileged built-in extension can identify a tab's native browser/context through Firefox Android's `ext-android.js` TabManager and inject a packaged fixed script with `ext-tabs.js` executeScript. Exact generated context matching is required before extraction; no caller-provided tab ID or script is accepted.
- HTTP channels can be guarded by exact `loadInfo.originAttributes`, including tabless requests. `nsHttpChannel::ContinuePrepareToConnect` calls the modify-request observers and then waits for resume before OnBeforeConnect. Suspending an owned hidden-context channel, authorizing off-thread, and pairing every path with resume/cancel is a plausible pre-connect HTTP guard. Every deadline, port loss and queue overflow must fail closed. A distinct `droidtop-hidden-UUID` namespace prevents unknown/closed hidden contexts from blocking visible `droidtop-UUID` sessions.
- Public WebExtension onBeforeRequest supports asynchronous blocking Promises, but its public tab/cookie-store fields cannot alone establish exact Gecko context for tabless workers. A tab-only filter must not be presented as complete confinement.
- Raw `GeckoWebExecutor` has anonymous/private/no-redirect flags and bounded fetch wrappers, but no per-session context ID and no JavaScript challenge execution. Its private flag is a shared private cookie jar. It is not a substitute for the scoped rendered-document requirement.

## Why the HTTP guard requires an isolated runtime

Gecko's per-docshell [allowDNSPrefetch](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/docshell/base/nsIDocShell.idl#L192) controls DNS prefetch for its subtree starting with the next document. It does not establish preconnect confinement.

[`Document::MaybePreconnect`](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/dom/base/Document.cpp#L13724) checks only the global `network_preconnect` preference and directly calls SpeculativeConnectWithOriginAttributesNative. It does not test the document's DNS-prefetch flag and does not create an HTTP request for the proposed observer to suspend. [HTTP 103 early hints](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/netwerk/protocol/http/EarlyHintsService.cpp#L92) can also initiate EarlyHintPreconnect with the channel's origin attributes.

The [speculative-connect observation](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/netwerk/protocol/http/nsHttpHandler.cpp#L2580) is a debug notification with a null subject, followed by the connection-manager path; it is not a cancellable per-context authorization hook. No supported GeckoSession per-context preconnect control was found in the pinned API. Changing Browser-wide networking preferences would affect the user's ordinary browser and is outside the approved solution.

Consequently, a namespace-scoped HTTP observer plus navigation guard is insufficient. The implementation uses a separately owned process/profile with pre-native startup restrictions, authenticated channel-specific proxy routing, exact cookie contexts and bounded lifecycle. Its restrictions never change ordinary Browser's runtime. The owned process also denies default/background HTTP channels that lack a live operation context.

There is an additional non-HTTP review item: GeckoView's [permission process actor](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/mobile/shared/actors/GeckoViewPermissionProcessChild.sys.mjs#L50) permits peer-connection requests. Do not claim an HTTP channel observer constrains WebRTC data-channel traffic. Per-context controls would need verification before any broader all-network isolation claim.

## JSON fidelity requirement

Firefox's [JSON converter](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/devtools/client/jsonview/converter-child.js#L98) changes JSON document content type to text/html, assigns a resource principal, and constructs a viewer application. body.innerText could return viewer labels. The owned profile disables viewer conversion; fixed textContent extraction validates UTF-8 JSON syntax and size. This is document text, not wire-byte/compression identity. Escaped values remain JSON; browser newline normalization may affect insignificant whitespace. Ordinary Browser's JSON-viewer preference is unchanged.

Required coverage includes genuine JSON, an HTML challenge followed by JSON, same-site and off-scope redirects, denied/private-network resources, speculative preconnect and early hints, large HTML/JSON, worker requests, port loss, cancellation and exact EOF/error handling. Mock policy tests cannot substitute for pinned Gecko integration and rig evidence.

## Other web panes to inventory next

- `app/.../StoreSignInActivity.kt` owns WebPage OAuth navigation callbacks, trusted store return-page scripts/cookie capture, and a separate Steam account/QR flow. A typed OAuth capability should return only a validated redirect/code (or explicitly typed cookie result), with state/PKCE and host-owned parsing. It must not accept the existing arbitrary script string as a plugin API field.
- `app/.../KeyWebPane.kt` owns service-specific WebView profiles, optional stay-signed-in behavior, configured capture pages and periodic key extraction. A future typed key-page capability needs an allowlisted service/capture schema, host confirmation before saving secrets, and dedicated profile retention/deletion. It must not reuse a hidden GET or checkout context or expose arbitrary selectors.
- `app/.../WebViewKeys.kt` owns companion keyboard placement through a fixed focus script/message listener. The embedded Gecko surface needs equivalent focus/IME/companion behavior to be verified; a rendered surface alone does not prove parity.

The concrete keyboard panel pad regression was fixed separately. These remaining web surfaces and networking limits are open review work, not evidence of completed migration.

## Isolated implementation progress

The startup adapter, generated profile, restrictions and shared transfer consumer compiled across Browser ABIs at `192fb90` (Android run 46088186832; hygiene 46088187099). The first complete provider attempt at `3c47f9f` lost its hosted runner during Build (46089729974), so it supplies no native compile result. Complete consumer gates are tracked on `ci/scoped-hidden-provider`; public activation remains a separate reviewed change. Compilation does not prove runtime containment or challenge success.

- The owned-profile preference list disables JSON viewer conversion, HTTP3, TRR, connectivity/captive-portal probes, speculative DNS/network prefetch and optional non-isolated subprocess roles. Exact profile, engine and effective native restrictions are checked. Restrictions are copied to the default branch before locking and read back afterward, because locking a user preference must not restore an unsafe default. Startup injection itself defines defaults: key presence is not independent evidence the engine implements a preference. Support comes from the pinned release source/build flags, not that presence test.
- Every HTTP channel in this dedicated runtime requires a live exact private operation context. Default/background/unrelated channels are denied. This extension is never installed in ordinary Browser. Successful suspends have a single resume across authorization, denial, timeout, unregister and port loss.
- A channel proxy filter selects an operation-specific loopback CONNECT gateway, explicit proxy authorization and connection isolation key. Unknown/expired channels cancel and receive a non-null dead-end proxy; null would mean DIRECT. Manual default proxy, empty bypass list, localhost proxying and disabled bypass prevent an unrelated direct path. The host must resolve, authorize and connect the SAME `InetAddress`; a preliminary DNS lookup plus Gecko's independent lookup is insufficient.
- Pinned [channel proxy API](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/netwerk/base/nsIProtocolProxyService.idl#L152) supports isolation keys. [Connection hashing](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/netwerk/protocol/http/nsHttpConnectionInfo.cpp#L274) includes that key. Plain HTTP proxy info does not automatically apply its authorization field; the privileged channel explicitly sets it. [CONNECT construction](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/netwerk/protocol/http/nsHttpConnection.cpp#L2055) copies it to the tunnel request; [origin serialization](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/netwerk/protocol/http/nsHttp.cpp#L496) removes proxy headers when using CONNECT. [Manual proxy failure](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/netwerk/base/nsProtocolProxyService.cpp#L1720) with no next proxy returns failure, rather than inventing DIRECT fallback.
- A static supposedly closed port is insufficient: another local service could own it. Before native startup, Browser binds its own ephemeral loopback reject-only listener and injects those ports; the startup adapter rejects unconfigured placeholder ports. The sink never reads, replies, resolves or forwards. Its descriptor remains reserved until native shutdown or owned-process retirement. A CI step is configured to compile/test this actual Java listener for port reservation, CONNECT rejection and no destination connection; no local JVM build/network test was run. The separate [system-request fallback](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/netwerk/protocol/http/nsHttpChannel.cpp#L4053) is also explicitly disabled with `network.proxy.failover_direct=false`. Where that optional feature is compiled out, the unused preference is harmless; where compiled in, its pinned getter must remain false.
- Fixed packaged extraction targets only the generated context. Owned-profile `devtools.jsonview.enabled=false` avoids viewer labels. Valid UTF-8 JSON/text uses document text; HTML uses rendered markup. This is document text, not wire-byte or compression identity. Missing status, invalid/ambiguous encoding, malformed JSON, unsupported MIME and overflow fail explicitly; truncated content never counts as success.

Node source tests exercise preference mismatches, proxy isolation/no-failover, background/worker denial, channel cleanup and real JSON/HTML/oversized extraction cases. They do not prove actual Gecko network/process behavior. Destination confinement, scope changes, redirect/subresource paths, TLS/SNI behavior and cancellation still require CI integration plus a later rig check before any runtime claim.

The bootstrap bypasses Gecko's optional configuration loader entirely. A small source-pinned Java adapter in `org.mozilla.geckoview` adds typed `RuntimeSettings.Pref` entries and verifies the resulting map before `GeckoRuntime.create`; the optional config path is explicitly empty. Pinned [`GeckoRuntime.init`](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/mobile/android/geckoview/src/main/java/org/mozilla/geckoview/GeckoRuntime.java#L510) passes that map into `GeckoThread.InitInfo`. [GeckoThread](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/mobile/android/geckoview/src/main/java/org/mozilla/gecko/GeckoThread.java#L489) supplies it before native environment initialization; [GeckoLoader](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/mobile/android/geckoview/src/main/java/org/mozilla/gecko/mozglue/GeckoLoader.java#L82) serializes typed defaults; [Preferences initialization](https://github.com/mozilla-firefox/firefox/blob/FIREFOX-ANDROID_160_0_RELEASE/modules/libpref/Preferences.cpp#L4697) loads them as defaults before IO-service preference reads. The adapter compiled at `192fb90` without reflection. A fresh generated profile prevents stale user overrides; only generated prior-process profiles beneath the canonical private root are removed without following symbolic links. Native attestation independently checks effective preferences/profile and isolated allocator before any operation.

Main-process forwarding uses a nonexported service and same-UID Messenger messages with separate process-control and operation lease binders. One control connection per loaded runtime/plugin keeps the restricted engine warm. A completed body, cancellation, failed/no-start operation or host death releases only that operation's lease; closed operations cannot accumulate to the 16-owner limit. Control unload detaches all its operations and unbinds. Idle authorization polling stops when no generated context remains.

When the final binding destroys the service, only the verified `:droidtop_web` process is retired: Gecko cannot initialize another native runtime in that same process, and blocked Binder calls cannot be reliably interrupted in Java. Fatal bootstrap/guard loss retires the same owned worker immediately, so warm bindings cannot retain a poisoned engine. Ordinary Browser remains separate. Rig checks must include more than 16 sequential document requests, concurrent contexts, cancellation/death, cold restart and normal Browser continuity; neither compilation nor source mocks prove that lifecycle.
